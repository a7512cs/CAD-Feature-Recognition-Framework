# 幾何一次匯入自有格式，不即時查詢 Host CAD

各家 Host CAD 的幾何資料格式不同，本框架必須有一層接入介面。我們選擇讓每家 CAD 的 adapter **一次性把整個模型匯入成本框架自有的 BRep**，而不是定義一組抽象幾何查詢介面、由 adapter 即時轉呼叫 Host CAD 的原生 API。

## Considered Options

- **一次匯入自有 BRep**（採用）— adapter 讀一次，之後演算法只面對我們自己的資料結構。
- **抽象幾何查詢介面** — 不複製資料，每次查詢即時轉呼叫 Host CAD。

## 為什麼

有些格式取得資料的成本極高：例如要拿到 face id 必須用 while 逐一走訪，每取一個 face 都很慢。如果演算法的每一次幾何存取都要穿過這層介面回到 Host CAD，辨識效能會被拖垮。統一成自有格式後，成本集中在匯入這一次，之後所有存取都是本地記憶體操作，而且演算法只需要面對一種穩定的資料表示。

## Consequences

- 匯入本身會有明顯的時間與記憶體成本，且是全量的，無法只匯入模型的一部分。
- 我們必須自行維護一份幾何資料模型；Host CAD 支援而我們的 BRep 沒有表達的東西，演算法就用不到。
- 辨識結果用的是我們自己的識別子，要回報給 Host CAD（例如高亮某個面）必須另外保存對照關係。
