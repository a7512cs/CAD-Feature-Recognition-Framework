# 上游重算後一律讓下游過時，不比對結果

當一個 Feature 被重新辨識，我們**無條件**把所有下游 Feature 標記為 Outdated，即使這次算出來的結果跟上次一模一樣。

## 為什麼

要做到「結果相同就不標記」，就必須為每一種 Feature 定義「什麼叫結果相同」，而這是 Recognizer 作者的責任。框架逼每個演算法實作一個可靠的比較函式，成本高又容易寫錯——少比一個欄位就會漏掉本來該重算的東西，而且是靜默出錯，使用者拿到的是錯的答案卻沒有任何警告。

保守重算的代價是慢；錯誤跳過的代價是給出錯的結果。我們選擇慢。

## Consequences

只改了一個不影響結果的參數（例如角度門檻 30 改成 31），仍然會讓整條下游鏈重算。如果將來這變成真實的效能痛點，可以再引入「由 Recognizer 選擇性提供結果指紋」的機制，但預設仍是無條件失效。
